## Verify your upgrade

1. Before changing dependencies, save an effective-rule snapshot with
   `basic-eslint snapshot`. If your current version does not support snapshots,
   record the existing lint output instead.
2. Update Basic and the framework or feature packs your project uses. Packages
   within the same major can have different minor and patch versions; follow
   their declared dependency and peer ranges instead of matching every version.
3. Run `basic-eslint compatibility` to check Node.js, ESLint, and installed
   package ranges, then `basic-eslint doctor` and `basic-eslint inspect` to
   diagnose setup problems and confirm detected features. Optional packs may
   require a newer Node.js version than the lean Basic package.
4. Run `basic-eslint diff` against the pre-upgrade snapshot, when available.
   Exit code 1 means effective rules changed; review those changes before
   refreshing the snapshot.
5. Run your lint script with zero allowed warnings, plus your project's type
   checks and tests. See the [editor and CI recipe](/guide/getting-started/#editor-and-ci)
   for a minimal lint script and workflow.

These checks validate your project after an upgrade. Maintainer release preflight
remains a separate gate.

## Maintainer release process

Release branches use `release/v<stable-semver>` and must match the Basic package version.
Both versioned release branches and Changesets-generated branches receive complete
preflight and a dependency audit before publishing from the merged main commit.
See the [release preparation and recovery guide](https://github.com/santi020k/eslint-config-basic/blob/main/.github/RELEASE_RECOVERY.md)
for validation, migration notes, recovery, and post-release verification.

## Moving from an older major

For v2, follow the [v2-to-v3 migration guide](/guide/migration-v2-to-v3/)
for the lean package boundary, optional package installs, and moved imports.
For v1, start with [v1-to-v2](/guide/migration-v1-to-v2/), then continue to
v2-to-v3. Review migration output before using `--write`.

For package-level release notes, continue to the [changelog index](/guide/changelog/).
